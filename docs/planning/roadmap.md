# aydinlearns roadmap

The plan for every update after the first build sprint: what each sprint contains, the jobs to
do, what it depends on, and when it is done. Written 2026-10-03, after sprint 1 closed.

**Starting a sprint in a fresh session:**
1. Read this file, then `2026-10-03-build-handoff.md` (what sprint 1 left behind) and
   `2026-10-03-build-record.md` (every ruling, every deferred finding).
2. Read the project `CLAUDE.md` and the design, `../superpowers/specs/2026-10-01-aydinlearns-v1-design.md`.
   The design is the authority; this roadmap and the plan's roadmap argue from it. Section §16
   holds the build order.
3. Settle the sprint's "Before starting" decisions with the owner, all in one batch.
4. Write the sprint's plan with the writing-plans skill, from its section below and the design.
   The plan is reviewed by the owner before anything is built.
5. Execute it subagent-driven, under the rules below.

**Slip rule (design §2.3):** when a slice misses its date, the content listed after it is
deferred (levels 6-7, later companies and datasets). The next slice is never compressed, and the
learner's effort is never the lever. Every slice goes live before the goal it serves.

## Rules for every sprint

| Rule | Detail |
|---|---|
| Reviews | One review per task. Fix only Critical and Important findings, once, accepted on test evidence, with no re-review. No pre-review concern rounds unless about correctness or security. Minors wait for the sprint's end |
| Agents | At most 4 subagents at once. Sonnet for simple tasks, Opus for complex ones |
| Commits | No commit, push or install without the owner's explicit request. Installs are asked as one batch |
| Keys | Answer keys never appear in the conversation, commit messages or PR text. Content is generated by background agents; reports name item IDs and check results only |
| DuckDB | Every instance anywhere (app, tests, fixtures, scripts, pipeline) has autoinstall and autoload off and sets TimeZone with SET after opening (R17). The runner follows R12 |
| Content | Generated and blind-solved by `../content/generator-brief.md` and `../content/blind-solver.md`. Every active item passes `npm run check:content` (C01-C16) |
| Grading | Bump `GRADER_VERSION` (now `1b.3`) with any change to pass or fail, the diagnosis, the partial score or the checks an attempt logs. Real attempts are logged now |
| Logs | Append-only, never edited by hand. A log schema change needs the owner's approval |
| Nothing is locked | No prerequisite, level or hint gates, ever (design §4) |
| Codex | After a PR merges, read its Codex comments, give a verdict on each, log them, and tell the owner the fix plan before fixing |
| Docs for Aydin | Short plain English, tables, no em dashes, no gendered pronouns |
| Done | Every check in the README's "Run and ship" passes, including `npm run test:e2e`, plus the sprint's own gate. One browser smoke test per slice |
