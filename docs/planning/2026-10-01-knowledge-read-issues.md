# Knowledge-bank issues from the 2026-10-01 planning read

These are raw findings from five parallel readers that read every aydinlearns knowledge file in full during the planning session. They come on top of `knowledge/review_2026-09-30.md`.

They are **not individually verified**. Slice 0 (design §15) adjudicates each one. A confirmed issue gets an ID in `knowledge/ERRATA.md`; a rejected one is noted there as rejected. Severity tags are the reader's own.

The design spec already settles some of them (for example the grading tolerance, the rating-map timing and the ID crosswalks). Where it does, the spec wins.

## 01 SQL curriculum, 02 mistakes and learning, 00 brief

### Issues not in the 2026-09-30 review

1. HIGH - Numeric tolerance hole in 02 §3.1: the pass rule |s-k| <= max(1e-6, 1e-6 x |k|) allows an error of about EUR 12 on a EUR 12.3M total, so a query that drops a small order still passes. Large sums are normal in the company data. 01's absolute 1e-6 does not have this problem. Fix: tolerance per precision class, and relative tolerance only at 1e-9 or less.
2. HIGH - The error taxonomy stops early. By hand count, only about 55 to 60 of 01's 138 card mistakes map to one of the 37 ERR IDs. The unmapped ones are concentrated in LVL-04 to LVL-07: missing PARTITION BY (WIN-01, WIN-03, PAT-08), RANGE vs ROWS ties (WIN-04), LAST_VALUE's default frame (WIN-07), 'row is not a day' gaps (WIN-03, WIN-05, PAT-03), averaging ratios (AGG-01, WIN-05), percent scale 0.15 vs 15 (BASICS-02), funnel step order and base (PAT-07), cohort offset days/30 (PAT-06), MRR reactivation (PAT-10). These all fall back to ERR-LOG-00, so error cards (RULE-03), trap items and ANL-01/02/09 cannot target them. 01 REC-04 expected the card mistakes to feed the log.
3. HIGH - Many beginner examples and exercises need concepts taught later. Need a JOIN: FILTER-01 Ex1 (promotions has no category column), FILTER-01 E3 (orders with a return), SORT-01 Ex2 (ad_spend_daily has no channel), AGG-03 Ex2/E3 (spend vs conversions), AGG-04 Ex1 (promo share per category). Need date truncation (SQL-DATE-01, taught in LVL-04): AGG-02 Ex1, E2 and E3, JOIN-01 E2. Since Claude Code will generate the LVL-1/2 exercises from these patterns (review #8), either ship denormalised beginner views or move SQL-DATE-01 (its only prerequisite is AGG-02) into LVL-02, and STR-01 (only needs BASICS-02) earlier.
4. HIGH - The attempt-log schema cannot record what the rules require. (a) RULE-19 cases rate several concept cards, but the schema has one card_id, fsrs_rating and fsrs_before/after per row. (b) attempt_number is 'per exercise instance', yet no instance ID exists, so episodes break when the same exercise is re-served in a session (RULE-08). (c) 01 REC-03's tags (world, QS, E1-E3) and the level are missing. (d) There is no free-text field for QS-02 'explain your approach' or the RULE-12 self-explanations.
5. MED - Nothing sandboxes learner SQL. Neither file restricts submissions to one read-only SELECT. DDL, DML, ATTACH, COPY, SET, INSTALL or multi-statement input could change the seeded tables for later exercises, or read answer-key tables if they live in the same database. Grade on fresh or read-only dataset copies and reject anything that is not a SELECT.
6. MED - Contradictions in the classification order. CHK-COLS-COUNT runs before mutant and grain checks, so a wrong-grain answer that adds its extra GROUP BY column to SELECT is reported as ERR-OUT-01, not ERR-LOG-07, even though LOG-07 lists COLS-COUNT as one of its own signatures. 'Stop at the first decisive result' conflicts with recording secondary_error_ids. The pass path (CMP static checks) is not in the order at all.
7. MED - 'Graded attempt' is defined three ways. 02 §4.4 says only executed attempts count. RULE-04 and §3.2 say syntax errors fixed within 60 s do not count, which implies a syntax error left for more than 60 s does. The schema's graded_attempt_number counts 'submissions that executed'. And §3.2 lets engine-raised SEM errors (SEM-01, SEM-05) have the same grace.
8. MED - Grader type normalisation in 01 GRADE-04 turns every number into a canonical decimal string. That makes text '10' equal to numeric 10, so CAST(x AS VARCHAR) answers would pass, contradicting 02's ERR-OUT-02. Check the type class before converting to strings.
9. MED - Rounding edge cases. 02's round(s,n) = round(k,n) wrongly fails float values sitting on a half boundary (0.1249999 vs 0.125). 01 instead uses a 0.005 tolerance. And JavaScript's Math.round rounds halves towards +infinity while SQL ROUND usually rounds away from zero, so negative growth rates can disagree. Do all rounding in DuckDB and compare with a half-unit tolerance.
10. MED - Grader trimming of trailing whitespace (02) makes SQL-STR-01 TRIM exercises (STR-01 E1, PAT-02 E3 normalised emails) pass even when the learner forgets to trim. These items need a trim_strings=false override.
11. MED - The pacing models conflict. 01's concept estimates are 45 to 90 min each (47.25 h in total inside the 128 h). 02's daily template gives 10 to 15 min per new concept (30 min for 3 on a 120-min day). The review flagged only the weekly hours and the GA4 split.
12. MED - Version namespace confusion that matters for pinning. 01 cites OPFS persistence tested with DuckDB-Wasm 1.32.0/1.33.1-dev, which are npm package versions. The review's 'lambda syntax needs 1.3 or later' and 02's example engine_version '1.3.2' are DuckDB core versions, and the review tested on native 1.5.6. Separately, the review's statement that '01 cites an OPFS write bug in the npm latest build' cannot be traced: no such text exists in 01 or anywhere in knowledge/. Pin and log both versions, and re-verify the bug claim before relying on it.
13. MED - Error-card explosion. RULE-03 creates a concept-plus-error card the first time any ERR-LOG or ERR-SEM ID appears for a concept: up to 46 x 25 combinations. Each needs trap exercises 'built to provoke that error' for that concept. There is no cap and no generic, parameterised trap template per error ID.
14. MED - About 18 of the 138 patterns cannot be graded by result set: BASICS-02 E3, FILTER-01 E3, TYPE-01 E2, JOIN-01 E3, JOIN-03 E1, WIN-02 E3, BQ-01 E1 (BigQuery syntax will not run in DuckDB), all CRAFT-01/02/03 items, and AGG-03 E3 as a two-stage item. Two-query equality items (WIN-06 E3, JR-09) need dual-query grading. 02's exercise_mode enum (lesson_check, practice, review, case, timed_drill, pretest) has no find-the-bug (QS-06), take-home (QS-04), flashcard (QS-05, JR-17, REC-06) or translation mode.
15. MED - Feedback placeholders have no defined vocabulary, and the prose and JSON templates differ (LOG-11, LOG-02). Many placeholders (expected_grain, parent and child, left_entity, expected_join, threshold, sort_col and direction, detected_agg) can only be filled from per-exercise or per-mutant metadata, which neither file includes in the exercise schema. ERR-LOG-15's prose cites a 'CHK-BOUNDARY-like check' that does not exist.
16. MED - Tables and columns implied by the 01 cards are missing from the DS schemas. This is more than 'skeletal': there are specific gaps such as leads, a plan change log, trials and activation, seats, online and store order tables, a second spend source, loaded_at, store region and opening date, orders.channel, status and shipping_fee, products.unit_cost, sales.on_promo, a calendar table, and GA4-shaped events with list-of-struct params. Check them against 05's company DDL before generating variants.
17. LOW-MED - 01's examples are dated 2026 (June 2026, Q1 2026, as_of 2026-06-30), which clashes with the review's re-dating of cases to 2024-2025. Use a per-dataset params.as_of_date. GRADE-09 bans now() and current_date only in answer keys; learner queries using them silently give date-dependent results, so they need a lint as well.
18. LOW-MED - NaN and Infinity (DuckDB float division by zero, per the review) need grader semantics: whether NaN equals NaN, NaN vs NULL, and an encoding in the JSONL log, since JSON has no NaN or Infinity.
19. LOW-MED - Level exit criteria are numeric only for LVL-01 (90%, 10 questions, 20 min) and LVL-06 (under 30 min each). JR-03's '90% on 5 problems' in practice means 5/5. JR-02 ('no NULL-tagged mistakes') and JR-05 (seeded fan-out bugs) need an error-family tag (NULL: SEM-04, LOG-03, LOG-17; fan-out: LOG-01, SEM-03) that 02 does not define.
20. LOW - CHK-INT-TRUNC tests S = trunc(K) or floor(K). In DuckDB, CAST(ratio AS INTEGER) rounds, so this check misses learners who cast; add round(K).
21. LOW - DIALECT-11 in 01 gives only PostgreSQL's ascending rule (NULLS LAST). 02 §2.7 correctly says PostgreSQL puts NULLs first on DESC, while DuckDB keeps NULLS LAST on DESC (review). That portability trap is missing from 01's DIALECT table and from SORT-01's mistakes. 01 also resolves two of 02's [UNVERIFIED] cells: PostgreSQL integer division [26] and BigQuery NULLS FIRST [34].
22. LOW - ANL-06 does not port to DuckDB (CAST rounds R deciles; json_extract returns JSON, not a number). ANL-02's SQL measures from the first occurrence, not the 'first correction', and returns counts, not a share.
23. LOW - The exam-mode retention of 0.93 does not say whether it covers all cards or only GA4. Applied globally, it would raise the SQL review load during exam fortnight.
24. LOW - BKT backing uses guess = 0.30 (02 §4.1), a multiple-choice value. For free-response SQL the guess is near 0; for 4-option GA4 questions it is 0.25.
25. LOW - RULE-16 raises or lowers variant difficulty under the same concept card. That confounds FSRS's per-card difficulty and the ANL-06 calibration; log the variant difficulty and consider it when re-optimising.
26. LOW - Day boundaries ('2 calendar days', '3 new per day', ISO weeks) are computed from UTC timestamps. Amsterdam is UTC+1/+2, so late-evening study can land on the wrong day; log a local date.

## 04 metrics and cases, 05 fictional companies

### Issues not in the 2026-09-30 review

44. HIGH: FIND-01-04's validation will likely fail by construction. The Sinterklaas window (20 Nov to 5 Dec) contains Black Week (25 Nov to 2 Dec 2024; 24 Nov to 1 Dec 2025, with web x2.2). If the multipliers stack (my assumption) and web share is 0.38, the measured ratios are about 1.6 x 1.23 = 1.96 for NL/BE and 1.1 x 1.23 = 1.35 for LU. 45. HIGH: LedgerLoop has no single source of truth for MRR. subscriptions has one mrr_local per subscription, but expansions are events (14,000 events vs 5,500 subscriptions), and no rule says mrr_local = SUM(mrr_delta_local). The CO-02 parameters also define churn, expansion and the price rise but no contraction or reactivation drivers. A ported CASE-SAAS-03 (and MET-SAAS-05) would show about zero contraction and reactivation, and every SAAS case depends on the derived mrr_monthly view.

47. HIGH: The porting count holds roughly, but the composition differs from the review's 13/7. With a European audience, the Los Angeles day boundary moves only the 00:00-07:00/08:00 UTC slice, which cannot plausibly produce Monday CPA above 1.4x. 52. MED: FIND-02-15 (CAC payback by channel via cumulative gross margin) needs a gross margin, but LedgerLoop has no COGS and PLANTS has no GM constant. This is a fourth finding that fails as written; the review lists three.

Examples: DOUBLE vs DECIMAL money (05 DDB-04 uses DECIMAL; 04's keys produce DOUBLE), or 100.0*a/b vs a/b*100 at x.x5, where the results differ by a full 0.1 or 0.01.
